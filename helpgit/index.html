Como Conectar e Versionar seu Projeto Unity com Git

Um passo a passo para ligar seu repositório vazio ao Unity, fazer commits, controlar branches e fugir dos erros clássicos, tipo os que corrompem prefabs ou estouram o limite do Git.

Repositório Vazio Criado
Projeto Unity Aberto
1

Ajustes Essenciais na Unity

Antes de qualquer comando, configure a Unity. Com o asset serialization em texto, o Git enxerga cada alteração em cenas, scripts e prefabs com clareza.

Force Text (Asset Serialization)

Acesse Edit > Project Settings > Editor.
Em Asset Serialization, selecione Mode: Force Text.

Visible Meta Files (Version Control)

No mesmo menu, confirme que o Version Control está em Visible Meta Files.

2

Crie o Arquivo .gitignore (Não Pule)

A Unity gera gigabytes de arquivos temporários e caches, tipo a pasta Library. Salve o conteúdo abaixo num arquivo chamado .gitignore na raiz do seu projeto.

.gitignore (Pasta Raiz do Projeto) 
# Caches e arquivos gerados automaticamente pela Unity
/[Ll]ibrary/
/[Tt]emp/
/[Oo]bj/
/[Bb]uild/
/[Bb]uilds/
/[Ll]ogs/
/[Uu]ser[Ss]ettings/
/[Mm]emoryCaptures/

# Visual Studio / Rider / VS Code
.vs/
.idea/
/*.csproj
/*.unityproj
/*.sln
/*.suo
/*.user
/*.userprefs
/*.pidb
/*.booproj
/*.svd
/*.pdb
/*.opendb
/*.VC.db

# OS store files
.DS_Store
Thumbs.db
Dica: arquivos pesados pedem Git LFS Textura 4K, modelo 3D pesado ou som .wav? Vale ativar o git lfs. Sem ele, seu repositório engorda e trava.
3

Ligue o Repositório Local ao Remoto

Abra o terminal (Git Bash, Prompt de Comando ou PowerShell) na pasta do seu projeto Unity:

Passo a Passo de Comandos 
# 1. Inicializa o Git na pasta do projeto
git init

# 2. Configura a branch principal para 'main'
git branch -M main

# 3. Conecta seu projeto ao repositório vazio (Substitua pela sua URL)
git remote add origin https://github.com/SEU-USUARIO/SEU-REPOSITORIO.git
4

Commits, Push e Pull

O ciclo básico: você grava a mudança e manda para o servidor. Depois, puxa as novidades dos outros.

Primeiro Commit e Push 
# Adiciona os arquivos
git add .

# Grava as alterações com uma mensagem
git commit -m "feat: configuracao inicial do projeto unity"

# Envia para o servidor (1ª vez)
git push -u origin main

# Nos envios futuros:
git push

# Para baixar atualizações:
git pull origin main
5

Branches e Merges

Crie mecânicas novas numa branch sem arriscar quebrar o jogo principal.

Fluxo de Branch 
# Cria e entra na nova branch
git checkout -b feature/pulo-do-jogador

# (Faça as alterações na Unity...)
git add .
git commit -m "feat: adicionado sistema de pulo"

# Volte para a main e junte a alteração
git checkout main
git merge feature/pulo-do-jogador
6

Boas Práticas para Unity & Git

Cuidado com Cenas e Prefabs

Duas pessoas editando a mesma cena (.unity) ou .prefab ao mesmo tempo? Resolver conflito nesses arquivos é um inferno. Prefira fases montadas com Prefabs e carregamento aditivo de cenas.

Ative o Git LFS para Assets Pesados

Texturas 4K, modelos 3D (.fbx) e áudios pesados (.wav) estouram o limite do Git. Com o Git LFS, esses binários ficam de fora e o repositório continua rápido.

Preserve os Arquivos .meta

O arquivo .meta guarda o GUID único de cada asset. Moveu ou apagou arquivo pelo explorador do sistema sem levar o .meta junto? As referências no Inspector somem.

Feche a Unity em Merges Grandes

Resolver conflito na mão ou trocar de branch com muita coisa mudada? Feche a Unity antes. Ela pode re-importar assets errado ou sobrescrever arquivos abertos.

Commits Frequentes e Focados

Commite a cada funcionalidade pequena que terminar. É muito mais fácil achar e corrigir um bug quando cada mudança vive num commit pequeno e bem explicado.

Utilize Clientes Gráficos (GUI)

Clientes visuais como GitHub Desktop, Fork ou GitKraken mostram direto na tela quais prefabs e meta files mudaram antes de você fechar o commit.
